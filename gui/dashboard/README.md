# Workflow Lens 本地仪表盘

Workflow Lens 面向研发负责人，用同一组本地 Markdown 证据回答三件事：效率怎么样、需求为什么返工、某个需求经历了什么。

## 启动

在 `ai-dev-workflow` 根目录运行：

```powershell
python gui/dashboard_server.py --workspace .
```

浏览器打开 `http://127.0.0.1:8766/`。仪表盘只监听 `127.0.0.1`，复用 `gui/server.py` 已有的只读任务与产物接口，不修改 PRD、状态或阶段产物。

自检命令：

```powershell
python gui/dashboard_server.py --self-test --workspace .
python gui/server.py --self-test --workspace .
node --check gui/dashboard/app.js
node --test gui/dashboard/app.test.js gui/dashboard/scoring.test.js gui/dashboard/app.score.test.js
```

## 数据口径

| 展示内容 | 唯一来源 | 缺失处理 |
|---|---|---|
| 需求总数、当前环节、当前状态 | `prds/*.md`、`work/<id>/state.md` | 显示未开始或读取异常 |
| 阶段时长、Token、等待、返工事件 | `work/<id>/metrics.md` | 仅累加已有精确值并显示覆盖分母，不估算、不补 0；旧返工数字不推算事件数 |
| 综合效率分 | 同一文档的“综合效率评分依据”、全部阶段尝试、唯一返工事件，以及显式生命周期中的验收状态 | 未验收归档、基准缺失或记录未完整核对时显示“暂不可评分”及原因 |
| 整体综合效率分 | 可正式评分需求按基准耗时加权 | 同时显示可评分/已验收归档数量与全部需求范围；无样本时保持 `N/A` |
| 返工原因 | `metrics.md` 中按唯一 ID 登记的返工事件类型与原因 | 同 ID 去重；冲突或无效事件不计数并提示；旧轮次单独保留待核对 |
| 甘特图与关联时间线 | `metrics.md` 的开始、结束及阶段顺序 | 多需求共享同一时间轴；没有时间时只显示产物节点，不推算日期 |
| 需求分类 | PRD id 与标题关键词 | 标记为启发式分类，只用于本地复盘导航 |

`cached_input` 是 input 的子集，`reasoning` 是 output 的子集；页面只读取每条记录明确给出的 `total`，不会把子集重复相加。需求头部 Token 为已有精确记录之和；部分尝试缺失时仍展示该已知总量，完整度由指标下钻中的 Token 覆盖分母标明。

综合效率分使用固定口径 `efficiency-v1`：

```text
100 × (T0 / max(T0,T))^0.35 × (K0 / max(K0,K))^0.25 × (N / (N+R))^0.40
```

T 是记录耗时合计（含等待与返工）；K 是总 Token；T0/K0 是实施前冻结的可比基准；N 是冻结验收项数；R 是独立缺陷返工事件数。100 分表示资源达到基准且零缺陷返工，不代表已部署或生产力提升百分比。总览展示整体分和覆盖范围；需求详情的指标区展示三项系数、基准/实际值、公式及不可评分原因。

基准与核对模板见仓库 [`workflow/references/efficiency-score.md`](../../workflow/references/efficiency-score.md)。在对应 `work/<id>/metrics.md` 中按真实证据维护唯一评分依据段落，再刷新看板。看板只读取这些数据，历史需求不会自动生成预算、补零或默认零返工。旧“有效产出单元/返工影响单元”比率保留原始证据，不参与综合评分。

## 交互

- 左侧导航可收回；窄屏时变成抽屉。
- `1` 打开总览，`2` 打开需求分析。
- `Ctrl+K`、`Cmd+K` 或 `/` 打开需求搜索。
- 需求分析的筛选与需求列表位于卡片抽屉；选择需求后抽屉自动收起，让画布占满可用宽度。
- 总览以紧凑指标带、并行需求泳道、趋势/状态带和诊断带组织，不使用卡片墙。
- 并行需求在同一时间轴上纵向对齐；点击需求泳道才展开阶段与尝试明细。
- 需求画布固定挂载 S1–S6 阶段摘要；虚线连接表示阶段回流。
- 点击阶段摘要打开阶段聚合与尝试列表，再点击尝试查看时长、Token、等待和备注。
- 阶段原文折叠并按需读取，缺失产物不会显示为通过。

## 当前边界

- 页面是只读分析视图，不创建 PRD、不确认闸口、不执行 Git 或 Shell 操作。
- 当前仓库的历史需求大多早于完整度量及评分基准接入，可能没有具备正式评分资格的样本；覆盖率用于揭示数据质量，不能通过隐藏缺失样本来提高分数。
- 页面不依赖外部字体、图表库或 CDN，断网时仍可使用。
