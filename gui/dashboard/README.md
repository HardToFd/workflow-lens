# Workflow Lens 本地仪表盘

Workflow Lens 面向研发负责人，用同一组本地 Markdown 证据回答三件事：效率怎么样、需求为什么返工、某个需求经历了什么。

## 启动

在 `ai-dev-workflow` 根目录运行：

```powershell
python gui/dashboard_server.py --workspace .
```

浏览器打开 `http://127.0.0.1:8766/`。仪表盘只监听 `127.0.0.1`，复用 `gui/server.py` 已有的只读任务与产物接口，不修改 PRD、状态或阶段产物。

自检命令：

```powershell
python gui/dashboard_server.py --self-test --workspace .
python gui/server.py --self-test --workspace .
node --check gui/dashboard/app.js
```

## 数据口径

| 展示内容 | 唯一来源 | 缺失处理 |
|---|---|---|
| 需求总数、当前环节、当前状态 | `prds/*.md`、`work/<id>/state.md` | 显示未开始或读取异常 |
| 阶段时长、Token、效率比、返工 | `work/<id>/metrics.md` | 显示 `—`，不估算、不按 0 参与平均 |
| 完成平均时长与 Token | 已归档且拥有完整度量的需求 | 同时显示覆盖分母；没有样本时保持 `—` |
| 过程效率比 | 有效产出单元 /（有效产出单元 + 返工影响单元） | 分母为 0 时显示 `—` |
| 返工原因 | `FAIL` 或返工记录的备注 | 仅做关键词归类，并保留原备注样本 |
| 甘特图与关联时间线 | `metrics.md` 的开始、结束及阶段顺序 | 多需求共享同一时间轴；没有时间时只显示产物节点，不推算日期 |
| 需求分类 | PRD id 与标题关键词 | 标记为启发式分类，只用于本地复盘导航 |

`cached_input` 是 input 的子集，`reasoning` 是 output 的子集；页面只读取每条记录明确给出的 `total`，不会把子集重复相加。

## 交互

- 左侧导航可收回；窄屏时变成抽屉。
- `1` 打开总览，`2` 打开需求分析。
- `Ctrl+K`、`Cmd+K` 或 `/` 打开需求搜索。
- 需求分析的筛选与需求列表位于卡片抽屉；选择需求后抽屉自动收起，让画布占满可用宽度。
- 总览以紧凑指标带、并行需求泳道、趋势/状态带和诊断带组织，不使用卡片墙。
- 并行需求在同一时间轴上纵向对齐；点击需求泳道才展开阶段与尝试明细。
- 需求画布固定挂载 S1–S6 阶段摘要；虚线连接表示阶段回流。
- 点击阶段摘要打开阶段聚合与尝试列表，再点击尝试查看时长、Token、效率和备注。
- 阶段原文折叠并按需读取，缺失产物不会显示为通过。

## 当前边界

- 页面是只读分析视图，不创建 PRD、不确认闸口、不执行 Git 或 Shell 操作。
- 当前仓库的历史需求大多早于 `metrics.md` 接入，因此完成平均值可能暂时没有样本；覆盖率本身就是需要暴露的数据质量信号。
- 页面不依赖外部字体、图表库或 CDN，断网时仍可使用。
