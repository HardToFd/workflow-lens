# 能力自检与降级配置

代理接入工作流的第一件事:对照下表自检,确定自己的运行档位。**档位只决定"动作由谁执行",环节顺序和产物要求永不降级。**

## 能力自检清单

| 能力 | 自检问题 | 有 | 无(降级) |
|------|----------|-----|-----------|
| 文件读写 | 我能直接读写工作区文件吗 | 正常运行 | 人类中继:代理输出产物全文→人保存;人粘贴文件内容→代理恢复状态 |
| shell 执行 | 我能运行 git/composer/go 吗 | 正常运行 | 代理产出"命令清单+期望输出说明"→人执行后贴回输出→代理解读 |
| 子代理/并行 | 我能派发并行调研任务吗 | S1/S4 并行加速 | 串行执行,产物不变 |
| 大上下文 | 我能一次装下 PRD+影响面代码吗 | 单会话跑多环节 | 单会话只跑一个环节,靠 state.md 交接备注续接 |
| 网络/远端 | 我能 push 和建 MR 吗 | 正常交付 | S5 产出 patch 文件(存 work/<id>/)+ MR 描述文本,人手工提交 |

## 运行档位速查

- **档位1 全能力**(Claude Code / Cursor / Codex CLI 等本地代理):全自动,只在闸口停
- **档位2 只读写不执行**(部分 IDE 插件/受限沙箱):所有阶段的 Shell/Git 命令都走人类中继,包括 worktree、分支、提交、验证和交付;文件读写与分析仍由代理完成
- **档位3 纯对话**(网页版 ChatGPT/Claude/Gemini 等):人类中继一切 IO。工作流退化为"结构化结对编程",但产物、闸口、状态机完全一致——换到档位1的代理可无缝接管续跑
- **⚠️ 档位混用是常态**:方案(S1/S2)用网页版强模型讨论、实现(S3~S5)交本地代理,靠 work/<id>/ 产物交接,这正是状态外置设计的目的

## 平台适配层(可选,非协议一部分)

平台特性只允许作为**快捷方式**存在,不允许承载协议逻辑:
- Claude Code:`.claude/commands/` 下的斜杠命令、CLAUDE.md 自动加载 → 均为薄壳,内容只是"读 AGENTS.md 照做"
- Cursor:`.cursorrules` 或 Rules 指向 AGENTS.md
- Codex/其他:多数已原生识别 AGENTS.md
- 判断标准:**删掉所有平台适配文件,工作流必须仍可通过"请先读 AGENTS.md"一句话启动**
