# 技能静态挂载配置

技能 = 对某个环节的增强逻辑,一个 `skills/*.md` 文件一个技能。技能选择以本文件为唯一配置来源，不进行任务检索、相似度打分或外部运行时路由。**挂载/取消挂载只改本文件的表格,不改 workflow/ 任何文档。**

## 挂载协议

1. 代理进入环节 X 前只查本表:`状态=启用` 且 `挂载点=X` 的技能,读其文件并执行其中的检查/增强
2. **通用红线(唯一权威表述)**:技能只能**增加**参照、检查或领域约束,**不得**改变状态机、闸口、需求范围、验证四态,或放宽 stages.md / projects.md 已有的任何要求。与协议冲突时协议赢,并在产物中记录冲突。
3. 技能文件格式:

```markdown
# 技能: <名称>
- 挂载点: S1 | S2 | S3 | S4 | S5 | S6(可多个;联测属 S4 内部,挂 S4 并以"项目启用 dual-baseline-test"为触发条件)
- 触发条件: 总是 | <条件,如"目标项目=X 且涉及报表">
- 作用: <一句话>
---
<增强逻辑正文:检查清单/参照代码路径/领域规则。挂载多个环节时,正文按挂载点分节>
```

## 各环节允许的增强面(挂载点参考表)

下表是"技能能挂到哪个环节、加什么类型内容"的参考;红线以上面第 2 条通用红线为准(本表不重复各环节完成判据,那是 stages.md 的权威内容)。人审挂载表变更时对照本表判断技能内容是否越界。

| 挂载点 | 允许的增强面 |
|--------|--------------|
| S1 解析 | 补充目标项目判定信号、影响面调研清单、领域术语与口径解释 |
| S2 方案 | 参照实现索引、设计约束/检查清单、DDL 与接口规范、已知风险清单、影响面分享图 |
| S3 实现 | 编码纪律、架构接入规范(注册表/分层等)、commit 约定 |
| S4 验证(含联测子步骤) | 追加验证项、专项自审清单(安全/性能/口径/并发)、dev 联测检查项 |
| S5 交付 | MR 描述附加小节、部署注意检查项 |
| S6 归档 | 沉淀模板、复盘检查清单 |

同一环节挂多个技能时,按挂载表行序执行;内容冲突时优先级:协议(workflow/)> 项目注册项 > 技能。

## 技能沉淀协议(S6 的产出回流到这里)

1. S6 归档时,把本需求可复用的经验写成 `skills/candidates/<名称>.md`(同技能格式,状态=候选)
2. 候选技能**不自动挂载**——人类审阅后移入 `skills/` 并在挂载表加行,才算生效
3. 判断"值得沉淀":下一个同类需求能否因此少走弯路?只对本需求有效的信息留在 work/<id>/ 即可,不要污染技能库
