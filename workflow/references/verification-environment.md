# 验证环境证据复用

用于当前项目的检查入口选择、已知环境限制或验证回流；不在所有阶段预加载，不增加新的闸口或独立报告。

在现有 `verify.md` 的“验证环境”小节留一条精简记录：

| 项目/工作目录 | 运行环境与版本 | 基线/目标提交 | 影响面及具体命令 | 结果/阻断原因 | 核对时间与证据 | 适用风险接受 |
|---|---|---|---|---|---|---|
| 注册名、绝对目录 | OS、PHP/Go/框架或相关扩展版本 | 实际 SHA | 相关文件/包及完整命令 | 四态；实际错误摘要 | ISO 8601 +08:00、原记录链接 | 日期、原话、范围；无则写无 |

- 下一需求引用同项目原记录，先比较环境版本、基线及涉及的初始化/依赖/影响面。四者仍适用时不重做同一诊断；变更了 PHP/Swoole、测试入口、相关依赖或基线初始化行为等才定向复查。版本未知或来源过期不能视为相同环境。
- 已知 Composer/Swoole 不可用、全仓分析资源耗尽等只能作为带环境和时间的历史证据，不是永久禁用测试。引用旧失败时保留历史 FAIL；当前未运行项写 NOT_RUN，并记录为何仍适用。
- PHP 必需验证展开为逐个变更 PHP 文件的 `php -l <具体文件>`，以及能覆盖本需求断言的现有定向测试。纯合同测试可用已确认适用的 `php vendor/bin/phpunit --no-configuration --bootstrap vendor/autoload.php <具体测试文件>`；需要框架运行时的测试不能强行换成无 bootstrap 入口并宣称等价。
- 配置中的全仓 `composer test` / `composer analyse` 为 advisory 时，不因其无法执行阻塞本地 test 分支准备或 S4 流转；必需项及实际业务联测仍按对应判据执行。不得用缩小测试目标掩盖本需求已发现的失败。
- 不为跑单测给业务代码加入测试进程初始化绕过，不删除断言，不临时放宽资源/校验标准制造 PASS。需要新的运行环境修复时单列影响和可用替代，不重复试探多个已知不可用环境。
- 原失败请求/payload 经脱敏后用于回归，保持层级、嵌套类型、缺失/空值与 ID 关联关系；回归输入、预期与输出范围都绑定验收项。假数据通过只证明相应合同，真实读写或部署未运行仍是 NOT_RUN。
- 已有风险接受和执行授权在相同范围内继承；新的风险、部署、合并或数据操作另按既有权限边界处理。本参考不授予真实 DB/Redis/媒体访问权限。
