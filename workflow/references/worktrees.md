# Worktree 隔离与清理

同一仓库并行需求优先使用独立 worktree。默认路径为仓库同级的 `<仓库名>-worktrees/<需求id>`。

创建或复用前核对路径、分支和基线归属；成功后立即在 `state.md` 的 `## 资源当前清单` 登记 resource_id、项目、精确绝对路径或分支、归属证据、已确认可再生文件及生成证据、清理授权、当前状态与最后核验时间。已有用户 worktree 不能仅因被本需求使用就标为本工作流创建。

S6 只清理带有该标记的临时 worktree。清理前：

1. 用 `git worktree list --porcelain` 核对精确路径。
2. 在目标 worktree 外执行检查和删除。
3. `git status --porcelain --ignored` 必须成功。若只有已登记且确认由本需求生成的可再生文件，在既有清理授权内逐个检查精确路径后可删除这些文件；删除后必须重跑命令并确认输出为空，再非强制移除 worktree。
4. 目标项目必须已经交付并通过闸口 C。

ignored 只表示 Git 忽略，不证明文件可再生、由本需求生成或可以删除；不得按目录名或扩展名批量猜测归属。含未知 tracked/untracked/ignored 文件、路径越界、检查失败或缺少清理授权时保留并说明原因，不强制删除。

任何移动或递归删除前确认最终绝对路径位于登记的需求资源目录内；使用同一 shell 的原生命令和字面路径。资源清理后逐条核对路径/本地与远端分支的实际状态，并更新资源当前清单；历史记录追加保留，当前摘要的清理字段独立于验收和部署结果。
