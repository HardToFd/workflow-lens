# 综合效率评分（efficiency-v1）

看板按需求计算 0–100 分，使用未舍入值聚合，仅在展示时保留一位小数：

```text
E = 100 × (T0 / max(T0, T))^0.35
        × (K0 / max(K0, K))^0.25
        × (N / (N + R))^0.40
整体分 = Σ(T0 × E) / ΣT0
```

- T 是该需求所有阶段、项目及尝试的记录区间耗时合计，包含等待及返工。并行区间照原口径分别计入，不代表真实需求历时或人工工时。等待只用于原因拆解，不再单独扣分；未知等待不影响已知 T。
- K 是所有尝试的精确总 Token 合计；cached input、reasoning 不重复相加。Token 是用量指标，不等同货币费用。
- T0、K0 是同类、相近规模需求的基准耗时和 Token，必须为正数；N 是实施前按统一粒度冻结的验收项数，必须为正整数。按项目技术、工作规模、阶段范围和模型用量口径选可比基准；R0–R3 风险等级不能替代规模。使用历史样本时记录样本来源，没有可信样本时可明确使用实施前确认的预算基准，不得事后拿实际消耗充当基准。
- R 是按 ID 去重后的 `defect` 事件数，覆盖全部回路。范围变更、环境阻塞、基线适配和流程迁移不增加 R，其实际资源消耗仍计入 T/K。质量权重有意表达对缺陷返工的关注，不是与资源消耗相互独立的成本估算。
- 100 分表示时间和 Token 达到基准且没有缺陷返工；成本项封顶为 1，节省更多资源不会抵消缺陷扣分。35%/25%/40% 是已选定的初始权重，调整时必须升级公式版本并保留原口径，不把分数解释为生产力提升百分比。

在该需求 `metrics.md` 中维护且只维护一个 `## 综合效率评分依据`。它属于过程度量证据，和 metrics 其他内容一样不进入业务项目提交。以下模板全部是占位符，不能直接作为已核对证据：

```markdown
## 综合效率评分依据

- 公式版本：efficiency-v1
- 基准版本：<实施前确认的基准版本>
- 基准分组：<技术栈、规模、阶段范围及模型口径>
- 基准耗时秒数：<T0，正数>
- 基准Token：<K0，正整数>
- 验收项数：<N，正整数>
- 基准冻结时间：<不晚于首次实施的带时区 ISO 时间>
- 基准依据：<plan.md 审批摘要/验收清单和基准来源>
- 记录核对：PENDING
- 返工核对：PENDING
- 核对记录数：<已逐项核对的阶段尝试记录总数>
- 核对事件数：<已去重核对的全部类型返工事件总数>
- 核对依据：<verify.md 中完整性与事件对齐的证据位置>
```

实施前确定前八个基准字段及对应审批证据，不因消耗超标回填更宽松基准或拆细验收项。实质性范围变更按现有审批流程更新范围版本和评分依据，旧版本留历史；不得把新基准伪装成原实施前基准。没有当时证据的历史需求保持不可评分。

验收后逐项确认所有项目、阶段和尝试均已记录，T/K 均有精确值，唯一事件已与验收记录对齐，再将两项核对改为 `COMPLETE`，填写当时的记录/事件总数和可复核的依据。事件数必须包含非 defect 类型；确实没有返工时明确填 0 并提供核对依据，空事件账本本身不能推出零返工。旧阶段有正数“返工次数”时，还需完成对齐并增加 `- 旧返工映射：COMPLETE`；原始旧数字保留，不参与 R 的计算。

正式评分还要求当前生命周期来自显式摘要、已归档、人工验收 PASS，且没有生命周期解析问题；交付材料明确标记 STALE 时也须先复核。不从 S6、合入、部署等字段推断验收。已有记录内数值完整不等于全流程完整，仍须上述完整性核对。缺失、重复或无效的基准/核对字段，返工事件冲突、记录数或事件数与核对数不符，均显示“暂不可评分”及具体原因，不填零、不把缺失维度权重转移给其他维度。

整体分只汇总具备评分资格的需求，按各自 T0 加权。看板同时展示可评分数/已验收归档数和全部需求数，揭示被排除样本；没有合格样本时不显示 0 分。阶段用时/Token 占比用于定位损耗，不再次参与评分。
